## 1. Ответы на требования Пункта 4 регламента

### 1.1. Архитектурная концепция Two-Stage Compact Neural-Symbolic
* **Проблема прямого подхода:** Попытка заставить компактную LLM (0.5B) генерировать развесистый JSON с точными символьными индексами цитат (`span = [start, end]`) и сложными правилами валидности дат приводит к высокой частоте синтаксических ошибок, галлюцинациям чисел и медленной генерации (длина ответа > 300 токенов).
* **Наше решение:** Конвейер разделен на два независимых контура:
  1. *Семантический контур (Нейросеть):* Компактная модель обучается генерировать сжатый 8-польный кортеж `[kind, name, attr, val, pol, vf, vt, idx]`. Длина генерации сокращается на ~65% (до 40–80 токенов), что дает кратный прирост скорости.
  2. *Символический контур (Invariant Calibration Engine v3.0):* Детерминированный постпроцессинг берет на себя выравнивание дат, привязку к онтологии `catalog.json`, цепочки статусов заявок и символьное выравнивание цитат по тексту реплик.

### 1.2. Поддерживаемые среды развертывания
1. **Локальное окружение (Python venv):** развертывание на Linux/macOS/Windows с минимальными зависимостями.
2. **Контейнеризация Docker:** одиночный контейнер с автоматическим переключением CPU/GPU и встроенным Healthcheck.
3. **Оркестрация Docker Compose:** профилированное управление сервисами `fact-extractor-cpu` и `fact-extractor-gpu`.
4. **Облачный кластер Kubernetes (K8s):** манифесты `Deployment` (3 реплики с ограничениями по CPU/памяти) и `Service`.
5. **Облачные блокноты (Google Colab / Kaggle):** запуск на бесплатных GPU типа Tesla T4 с сохранением артефактов.

## 3. Краткое руководство по развертыванию

### 3.1. Развертывание в Docker
```bash
# Сборка образа
cd 02_docker_service
docker build -t mws-compactfact:latest .

# Запуск на CPU (без видеокарты)
docker run -d --name mws-api -p 8000:8000 -e INFERENCE_MODE=point1_cpu mws-compactfact:latest

# Запуск на GPU (NVIDIA CUDA)
docker run -d --name mws-api -p 8000:8000 --gpus all -e INFERENCE_MODE=point2_05b mws-compactfact:latest
```

### 3.2. Развертывание в Kubernetes
```bash
kubectl apply -f - <<EOF
apiVersion: apps/v1
kind: Deployment
metadata:
  name: compactfact-extractor
  namespace: default
spec:
  replicas: 2
  selector:
    matchLabels:
      app: compactfact
  template:
    metadata:
      labels:
        app: compactfact
    spec:
      containers:
      - name: extractor
        image: mws-compactfact:latest
        ports:
        - containerPort: 8000
        env:
        - name: INFERENCE_MODE
          value: "point1_cpu"
        resources:
          requests:
            cpu: "250m"
            memory: "512Mi"
          limits:
            cpu: "1000m"
            memory: "1536Mi"
EOF
```
